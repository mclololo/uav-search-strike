## 1. 已确认约束

- 用户于 2026-09-10 明确：LoRA、视觉层微调和新增检测头属于赛事允许的“使用九格模型”。此项不再列为待确认。
- 启用九格时，任务全程禁止运行 YOLO 推理，不能以打击速度要求、丢框、超时或恢复为由切回 YOLO。
- 新检测头必须实际使用九格视觉特征；不能将已有 YOLO 改名或包装后作为九格检测头。
- 数据采用原始相机图像。用户已选择 YOLO 作为离线教师和预标注工具；本轮采用人工复核后的 bbox。正式九格任务全程禁用 YOLO。
- 本阶段训练目标是检测与视觉定位，不要求先训练 VLN；自主选择搜索视点、语义导航可作为后续独立扩展。
- 其他辅助算法和区域先验的规则边界不由上述两条口径自动推定。现有区域坐标、yaw 等审查项仍按 `AGENTS.md` 处理。
- 原始模型保留，实验产物单独保存。合成空白图只验证训练程序，不能作为任务识别能力的证明。

### 第四步：标注并校验这 30 张（T08）

1. 在云端桌面浏览器打开实验 `scripts/annotate.html`，选择 `data/images/pilot_001`；或把图片下载到本地，用本地同名页面标注。

3. 方框边界定义先与物理尺寸参数核对；不能仅凭既有 README 的“外框”建议认定尺寸已经匹配。首批默认外框标注一经选定需保持一致；必要时调整几何参数。
4. 气球只框主体，不包含小车或长绳。空画面点击“确认无目标”；有物体但无法确定类别/边界时跳过整图，避免产生漏标负样本。
5. 导出 `pilot_001.jsonl`。浏览器下载不会自动写入云端训练目录，须放入 `data/annotations/`。云端原图还在时只需上传 JSONL，不重复覆盖图片。

### 第五步：扩成第一版数据集（T07～T09）

建议先完成约 6 次独立场景采集，累计 300～500 张去重且人工复核的图片。这个数量是试验起点，不保证模型效果。

- 每类均覆盖远/中/近距离、偏心视角、不同高度、遮挡和运动变化；验证集与测试集也必须有四类实例。
- 首批可安排约 10%～20% 确认无目标画面，后续按误报情况调整。不要为了凑数量保留大量相同画面。
- 同一飞行即使分多个目录，也保留同一 `scene_id`；不能靠改目录名让相邻帧进入不同集合。
- 例如 `run_001～run_004` 训练、`run_005` 验证、`run_006` 测试。这些场景需要真实存在，且应覆盖四类目标。

数据完成后，以下已有脚本可直接执行：

```bash
python scripts/prepare_dataset.py --data-root data --annotations data/annotations --output data/v1 --val-scenes run_005 --test-scenes run_006
python scripts/fm9g_grounding.py validate --data-root data --train data/v1/train.jsonl --val data/v1/val.jsonl
```

`DATA_VALID` 只表示格式、尺寸、路径和集合检查通过，不保证人工框准确或数据覆盖充分。还需审阅 `data/v1/dataset-summary.json` 及抽样图片。`data/v1` 已存在时创建新的版本目录，不覆盖已用于实验的数据集。

## 6. 有数据之后怎么训练

### 6.1 图文 LoRA 基线（T10）

先用真实验证图片测原始模型，再运行现有 LoRA 入口，比较同一组验证图片。需要补上批量预测和 IoU/中心误差/空图误报/颜色混淆/JSON 合法率/时延分位数评估；现有 `infer` 只是单图输出，`best.json` 只按验证 loss 选择 checkpoint。

实际数据校验通过后：

```bash
python scripts/fm9g_grounding.py train --data-root data --train data/v1/train.jsonl --val data/v1/val.jsonl --output checkpoints/grounding-r16-run001 --rank 16 --alpha 32 --learning-rate 5e-5 --epochs 2 --accumulation 8 --slices 2
```

现有实现固定为单卡物理 batch=1，累积 8，BF16；输出目录必须不存在。目前不支持优化器断点续训，不把重复启动当成续训。保留原有自然语言解析用例做回归，不使用只学会空目标的 `SMOKE-ONLY` adapter 作为初始模型。

### 6.2 优先评估非 YOLO 检测头（T11）

这项实现可在数据采集期间独立推进，不必等待完整 LoRA 实验结束：

1. 检查九格视觉编码器的空间特征布局和切片映射，确认如何对应原图的气球与方框。
2. 选择已有成熟非 YOLO 检测实现的匹配、分类和框回归组件，接到九格视觉特征；不从头重新发明整套检测算法。
3. 先冻结视觉编码器训练新增头，再依据验证集决定是否微调视觉末层/resampler。新增头的空间输入不一定经过现有 resampler，需要实际核查。
4. 使用相同像素 bbox 数据，按该头需要的格式转换；图文训练使用文本交叉熵，检测头需要相应分类和 L1/GIoU 等损失，不能直接套现有 `train` 命令。
5. 验证输出为空、多目标、四类分类、框尺度、保存和重载；测采图到可用框的 p50/p95 及最坏情况。

无需再为“是否允许新增头”请求确认，但仍必须证明头实际利用九格视觉特征，且任务全程无 YOLO。没有数据或测速结果前，不承诺检测头必然达到某个 FPS。

## 7. 控制接入和验收条件

1. `/objects` 必须使用当前约定的四个精确类名和原图像素坐标；不能将 0～1000 坐标直接写入消息。图片缩放、裁剪和切片均须逆变换。
2. 保留采集时间、推理完成时间和最后真实观测时间，区分真实观测与预测。使用图像拍摄时的姿态进行三维定位，不能用当前姿态解释数秒前的框。
3. 跟踪器需要读取新的 RGB 图像。现有 Kalman 的高频预测/发布不证明感知高频更新；不得通过刷新时间戳掩盖旧观测。
4. 几何、颜色和质量筛选须有实际验证依据。模型生成的自报 confidence 不能直接当作校准概率。
5. 开始用 rosbag 和影子运行验证输出，不向飞控下发命令；再逐步做静态/低速/移动目标和完整任务。
6. 更新 launch、动态 BT 参数和静态测试入口，确认没有 YOLO 节点、YOLO 权重加载或回退调用。目标失效走重新检测、悬停或失败退出。
7. 需要追踪单独的打击结果；外层 `ForceSuccess` 可能让打击失败后整套任务仍返回 SUCCESS，不能将任务总结果作为命中证据。
8. ROS 接口或节点变更后执行 `catkin_make`，并记录全程日志、感知窗口和真实控制影响。目前这些构建和闭环检查尚未进行。
9. 保存可复现的权重、adapter/检测头、数据集哈希、提示词、依赖、launch 和代码版本。数据盘不随镜像保存，释放实例前另行导出。
