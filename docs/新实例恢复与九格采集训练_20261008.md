## 3. 启动仿真并采集

先在云桌面终端启动任务环境：

```bash
conda activate demo
cd /home/ubuntu/catkin_ws
PERCEPTION_BACKEND=fm9g ./sim_env_start.sh
```

启动脚本完成进程清理后，再在独立终端启动 `roslaunch mavros px4.launch` 和 `cd /home/ubuntu/PX4PSP && ./SITLRun.sh`。脚本会结束先前 MAVROS 进程，不要在它之前启动 MAVROS。

YOLO 离线采集轮次使用 `PERCEPTION_BACKEND=yolo ./sim_env_start.sh`。输入的自然语言任务不会切换检测器；更换后端须结束任务并重启环境。九格任务运行全程不能使用 YOLO 兜底。

原图采集：在单独终端初始化 `cloud_env.sh` 后，先开始采集，再到 LLM Mission 窗口输入任务。

```bash
rostopic hz /rflysim/sensor1/img_rgb
```

看到图像持续刷新后按 `Ctrl+C` 退出频率查看，然后执行：

```bash
RUN_ID="flight_$(date +%Y%m%d_%H%M%S)"
"$PY" "$TOOL/capture_frames.py" --data-root "$DATA" --require-mount /home/ubuntu/fm9g-data --run "$RUN_ID" --scene-id "$RUN_ID" --interval 1 --seconds 600 --max-frames 600
```

每次飞行使用新 `RUN_ID`。任务完成后采集终端按 `Ctrl+C` 正常关闭文件。原图、`frames.jsonl` 和 `capture.json` 位于 `data/images/<RUN_ID>/`。采集程序本身不会发送飞行指令。

仅在 `/objects` 的唯一发布者为 `/object_detection_node` 的 YOLO 采集轮次，可改用下面的预标注命令；不要把九格的输出错误标成 YOLO 教师标签：

```bash
rostopic info /objects
"$PY" "$TOOL/capture_pseudo.py" --data-root "$DATA" --require-mount /home/ubuntu/fm9g-data --run "$RUN_ID" --scene-id "$RUN_ID" --interval 1 --seconds 600 --max-frames 600
```

## 5. 生成新数据集并训练

结束仿真及大模型进程，避免与训练争用 GPU；训练时不要运行会清理 Python 进程的仿真启动脚本。新终端先 source `cloud_env.sh`。

列出可用 scene：

```bash
"$PY" -c 'import collections,json,pathlib,sys; rows=[json.loads(x) for p in pathlib.Path(sys.argv[1]).glob("*.jsonl") for x in p.read_text(encoding="utf-8").splitlines() if x.strip()]; print(json.dumps(dict(collections.Counter(r["scene_id"] for r in rows)),ensure_ascii=False,indent=2))' "$ANNO"
```

选两个完整独立飞行作验证和测试，其余训练；不能随机拆相邻帧。下面两个场景适合复现本次恢复数据。新增训练数据后，若已根据旧测试结果调整方案，应补独立飞行作最终测试。

```bash
VAL_SCENE=flight_20260923_093827
TEST_SCENE=flight_20260922_161932
TAG=$(date +%Y%m%d_%H%M%S)
DATASET="data/dataset_$TAG"
RUN="fcos-$TAG"
"$PY" "$TOOL/prepare_dataset.py" --data-root data --annotations "$ANNO" --output "$DATASET" --val-scenes "$VAL_SCENE" --test-scenes "$TEST_SCENE"
cat "$DATASET/dataset-summary.json"
```

检查 train/val/test 的数量、四类框及 warnings。正式训练命令整行粘贴：

```bash
nohup "$PY" -u "$TOOL/fcos_grounding.py" train --base /home/ubuntu/model/FM9G4B-V --data-root data --train "$DATASET/train.jsonl" --val "$DATASET/val.jsonl" --output "checkpoints/$RUN" --epochs 8 --learning-rate 0.0001 --image-size 448 --score-threshold 0.2 --seed 42 > "logs/$RUN.log" 2>&1 < /dev/null &
echo "RUN=$RUN DATASET=$DATASET PID=$!"
tail -f "logs/$RUN.log"
```

按 `Ctrl+C` 只退出 tail；nohup 训练继续，关机仍会中断。完成标志是 `DETECTOR_TRAIN_FINISHED`。输出目录必须全新。脚本冻结九格视觉编码器，训练特征投影、多尺度卷积和 FCOS 分类/回归/centerness；每轮保存 `head.safetensors` 与 `val-metrics.json`。`best.json` 按验证 F1 选择最佳 epoch。当前没有从旧 head 续训或优化器断点恢复功能，`--head` 用于 eval。

## 6. 验证、测试与部署

先在验证集导出低阈值预测，选阈值：

```bash
HEAD=$("$PY" -c 'import json,sys; print(json.load(open(sys.argv[1]))["head"])' "checkpoints/$RUN/best.json")
"$PY" "$TOOL/fcos_grounding.py" eval --data-root data --annotations "$DATASET/val.jsonl" --head "$HEAD" --output "eval/${RUN}-val-raw" --image-size 448 --score-threshold 0.01
"$PY" "$TOOL/select_fcos_threshold.py" --predictions "eval/${RUN}-val-raw/predictions.jsonl"
```

将阈值设置为验证选择的值；`0.43` 是既有启动配置，不能由测试集调参：

```bash
THRESHOLD=0.43
"$PY" "$TOOL/fcos_grounding.py" eval --data-root data --annotations "$DATASET/test.jsonl" --head "$HEAD" --output "eval/${RUN}-test" --image-size 448 --score-threshold "$THRESHOLD"
cat "eval/${RUN}-test/metrics.json"
"$PY" "$TOOL/diagnose_fcos_errors.py" --predictions "eval/${RUN}-test/predictions.jsonl" --threshold "$THRESHOLD"
```

评估没有 `--resume`，目录存在时用新名称。重点看四类 Recall/F1、空图误报、中心误差、平均/p95 耗时。离线耗时包含该评估器的读图与检测时间，但不代表 ROS 排队、传输和飞行控制总延迟。

合格后把 head 复制到系统盘新目录，并用显式路径试运行：

```bash
DEPLOY="/home/ubuntu/model/experiments/fm9g4b_grounding/deployment/$RUN"
mkdir "$DEPLOY"
cp "$HEAD/head.safetensors" "$DEPLOY/head.safetensors"
sha256sum "$HEAD/head.safetensors" "$DEPLOY/head.safetensors"
cd /home/ubuntu/catkin_ws
PERCEPTION_BACKEND=fm9g FM9G_HEAD="$DEPLOY" ./sim_env_start.sh
```

仍用 `--image-size 448` 和启动脚本阈值 0.43 时，上面的启动命令可直接使用。若训练/评估改了分辨率或节点阈值，必须同步修改启动脚本中 `ros_fcos_node.py` 的参数，使离线评估与在线设置一致。

另开终端 `rostopic info /objects`：九格唯一发布者应为 `/fm9g_spatial_detector`。先检查窗口与真实图像，再测试红球、蓝球和完整任务；日志 `SUCCESS` 不单独证明物理命中。

## 8. YOLO 启动脚本执行权限报错

若 YOLO 窗口提示 `Cannot locate node of type [det_color_conda.sh] in package [object_det]`，先检查脚本是否存在及是否可执行。2026-10-08 的实例恢复曾把该脚本权限复制为 `666`，导致 ROS 不将它识别为可执行节点；文件内容和 Linux 换行符正常。已将云端该脚本修复为 `755`，并补全恢复打包和解包流程中的 `.sh` 执行权限。

如果以后重新同步后再次遇到，在本地 PowerShell 执行：

```powershell
ssh -p 30624 root@120.209.70.195 "chmod 755 /home/ubuntu/catkin_ws/src/object_det/scripts/det_color_conda.sh"
```

在云端原 YOLO 终端按 `Ctrl+C` 结束失败的 launch，再执行下面两行即可重启检测器，无需重启整个仿真。只在本轮选择 YOLO 且 `/objects` 没有其他检测器发布时使用；九格模式应启动九格检测器。

```bash
source /home/ubuntu/catkin_ws/devel/setup.bash
roslaunch object_det detection_color.launch
```

同步验收除了比较文件哈希，还须以 `ubuntu` 检查 `test -x` 和实际 ROS 节点启动。Ego-Planner 的 `WAIT_TARGET` 表示正在等待规划目标，不是这个检测器启动错误。
