# 组员从 Git 克隆、同步并运行任务

本版本使用九格语言模型解析指令，冻结九格视觉编码器加 FCOS 检测头识别方框和三色气球；实时检测不调用 YOLO。服务器须来自赛事/GPUFree 镜像，已有 ROS Noetic、PX4/RflySim、CUDA、conda `demo` 和 `/home/ubuntu/model/FM9G4B-V`。

采用新的工作区目录部署，不覆盖服务器原 `/home/ubuntu/catkin_ws` 或 `/home/ubuntu/model`。当前启动脚本直接使用仓库中的任务解析脚本、提示词、九格检测节点和检测头，所以不需要覆盖云端旧的三份模型代码文件。

## 1. 本地克隆

安装 Git 和 Git LFS，在本地 PowerShell 执行（已有目录时换一个新目录）：

```powershell
git lfs install
git clone --branch feature/perception --single-branch https://github.com/mclololo/uav-search-strike.git
cd uav-search-strike
git lfs pull
Get-FileHash -Algorithm SHA256 tools/fm9g_grounding/deployment/fcos-recovered-20261008/epoch-04/head.safetensors
```

检测头 SHA-256 应为 `7a7cd85a5152a4b354efd134e7126c7e8b0732dbe2fe609f805ebe7aad2fa882`，大小 29,608,860 字节。必须下载真实 LFS 文件，不能只拿文本指针。项目合并到其他发布分支后，将 `--branch` 改为该分支；以 `git rev-parse HEAD` 记录实际版本。

## 2. 生成并上传提交版本

本地安装 Python 3.10 或更高版本。打包器只导出 Git 提交中的文件，并按 Git LFS 哈希嵌入实检测头；不打包 `.git`、本地未提交副本、基础模型、`best.pt`、原图或训练数据。

```powershell
$Version = git rev-parse --short HEAD
python tools/package_cloud_workspace.py --output "tmp/uav-$Version.tar.gz"
$Port = 30624
scp -P $Port "tmp/uav-$Version.tar.gz" "root@120.209.70.195:/tmp/uav-$Version.tar.gz"
```

端口和主机改为自己实例平台显示的信息。打包器拒绝覆盖已有压缩包，重复打包请使用新文件名。记录打包器输出的 `archive_sha256`，上传后在服务器以 `sha256sum` 核对。

## 3. 在新目录解包

通过 SSH root 终端执行。下面把 `VERSION` 改为本地的提交短哈希，目录已存在时命令停止，不复用旧目录：

```bash
VERSION=填写提交短哈希
RELEASE="/home/ubuntu/uav-releases/$VERSION"
test ! -e "$RELEASE" && mkdir -p "$RELEASE"
```

若目录已存在，换新的目录名，不要继续解包。确认上述成功后执行：

```bash
sha256sum "/tmp/uav-$VERSION.tar.gz"
tar --keep-old-files -xzf "/tmp/uav-$VERSION.tar.gz" -C "$RELEASE"
chown -R ubuntu:ubuntu "$RELEASE"
```

仅新目录改变所有权；不改动旧工作区、模型、PX4 或数据盘。压缩包保留了 `src/CMakeLists.txt` 的 ROS 符号链接和 ROS 脚本执行权限，避免 Windows 打包后的 catkin/节点启动错误。

可选的 YOLO 模式需要服务器原来的 `best.pt`。只创建链接，不复制或移动权重：

```bash
test -f /home/ubuntu/catkin_ws/src/object_det/models/best.pt
mkdir -p "$RELEASE/src/object_det/models"
ln -s /home/ubuntu/catkin_ws/src/object_det/models/best.pt "$RELEASE/src/object_det/models/best.pt"
chown -h ubuntu:ubuntu "$RELEASE/src/object_det/models/best.pt"
```

若原镜像权重在其他位置，改为真实原件路径；没有权重仍可运行九格。后续升级再次部署到新的版本目录，不能覆盖已有版本或使用 `--delete`。

## 4. 独立环境与编译

在 ubuntu 云桌面终端执行。设置 `RELEASE` 为刚才的新工作区，以下环境检查和编译不会启动任务：

```bash
RELEASE=/home/ubuntu/uav-releases/填写提交短哈希
conda activate demo
if [ ! -x /home/ubuntu/.conda/envs/fm9g-train/bin/python ]; then /opt/conda/bin/conda create --prefix /home/ubuntu/.conda/envs/fm9g-train --clone /opt/conda/envs/demo --offline --yes; fi
/home/ubuntu/.conda/envs/fm9g-train/bin/python -m pip install --no-cache-dir peft==0.13.2
source /opt/ros/noetic/setup.bash
cd "$RELEASE"
catkin_make -j4
source devel/setup.bash
/home/ubuntu/.conda/envs/fm9g-train/bin/python -c 'import torch,torchvision,transformers,rospy; from common_msgs.msg import Objects; print(torch.__version__,torchvision.__version__,transformers.__version__,torch.cuda.is_available())'
/home/ubuntu/.conda/envs/fm9g-train/bin/python tools/fm9g_grounding/fcos_grounding.py probe --head tools/fm9g_grounding/deployment/fcos-recovered-20261008/epoch-04
```

已核对运行版本为 PyTorch 2.3.1、torchvision 0.18.1、transformers 4.44.2。其他依赖见 `tools/fm9g_grounding/requirements-runtime.txt`；镜像版本不同只在独立 `fm9g-train` 中调整，不改装仿真 `demo`。`probe` 是离线模型加载检查，不代表飞行验收。

## 5. 执行任务

先结束旧任务环境，确认无人机已撤防且没有正在执行的任务。在云桌面终端先启动新工作区的任务环境：

```bash
conda activate demo
cd /home/ubuntu/uav-releases/填写提交短哈希
PERCEPTION_BACKEND=fm9g ./sim_env_start.sh
```

等待启动脚本完成进程清理并打开窗口。当前脚本会清理已有 ROS/Python 进程，所以 MAVROS 必须在清理之后启动；先启动 MAVROS 再运行本脚本会把它结束。接着另开终端：

```bash
conda activate demo
source /home/ubuntu/uav-releases/填写提交短哈希/devel/setup.bash
roslaunch mavros px4.launch
```

另一个终端启动 SITL：

```bash
cd /home/ubuntu/PX4PSP
./SITLRun.sh
```

启动脚本仍保留原来的进程清理逻辑，请只在独立比赛实例运行；不要把它用于与其他开发进程共用的 ROS 会话。等待 LLM Mission 和 FM9G Detection 就绪；另开终端 source **同一版本的** `devel/setup.bash` 并检查：

```bash
source /home/ubuntu/uav-releases/填写提交短哈希/devel/setup.bash
rostopic info /objects
rostopic hz /objects
```

唯一发布者须为 `/fm9g_spatial_detector`，检测窗口应显示实际相机图像与 bbox。此时在 LLM Mission 窗口输入任务，如“飞机起飞，然后穿过框，再识别二维码，再穿回框，然后打击红色气球，完成后返回起点并降落”。二维码仍由 ArUco/QR 节点处理。

结束一轮后再切换后端；改用 YOLO 时运行 `PERCEPTION_BACKEND=yolo ./sim_env_start.sh`，并核对 `/objects` 的唯一发布者为 `/object_detection_node`。任务文字不切换后端，九格过程中不使用 YOLO 兜底。

`/mission_result` 的 `SUCCESS` 表示行为树完成，不单独证明气球实际命中。每位成员仍需在自己的实例进行飞行验收并保留视频/日志；当前版本的隔离构建和离线测试不能代替此验收。

## 6. 采集和训练

九格在线推理不依赖训练数据盘。采集和训练需要准备实验数据目录并人工恢复 bind mount，按 [新实例恢复与九格采集训练](新实例恢复与九格采集训练_20261008.md) 操作；source 所部署版本的 `tools/fm9g_grounding/cloud_env.sh`，该脚本自动选择所在工作区的 `devel/setup.bash`。不增加自动挂载服务或改动 fstab。

## 7. 首次准备训练数据盘（需要采集/训练时）

若服务器还没有训练实验目录，先通过 root SSH 执行下面命令。只在实验目录和 ubuntu 挂载入口都不存在时初始化；任一路径存在即停止，按恢复手册检查现有内容，不替换已有目录或链接。数据盘训练文件不在 Git 中，须自行采集并上传 reviewed JSONL。

```bash
set -e
test ! -e /home/ubuntu/model/experiments/fm9g4b_grounding
test ! -L /home/ubuntu/model/experiments/fm9g4b_grounding
test ! -e /home/ubuntu/fm9g-data
test ! -L /home/ubuntu/fm9g-data
test -d /root/gpufree-data
mkdir -p /root/gpufree-data/fm9g4b_grounding/data/images /root/gpufree-data/fm9g4b_grounding/data/annotations /root/gpufree-data/fm9g4b_grounding/checkpoints /root/gpufree-data/fm9g4b_grounding/eval /root/gpufree-data/fm9g4b_grounding/logs
mkdir /home/ubuntu/fm9g-data
mount --bind /root/gpufree-data/fm9g4b_grounding /home/ubuntu/fm9g-data
mkdir -p /home/ubuntu/model/experiments/fm9g4b_grounding/deployment
for part in data checkpoints eval logs; do ln -s "/home/ubuntu/fm9g-data/$part" "/home/ubuntu/model/experiments/fm9g4b_grounding/$part"; done
chown -R ubuntu:ubuntu /home/ubuntu/fm9g-data /home/ubuntu/model/experiments/fm9g4b_grounding
```

这些命令须在独立的 root SSH 会话运行，`set -e` 会在检查失败时停止，不能放入采集/训练桌面终端。此后按恢复手册人工挂载；ubuntu 采集/训练终端 source 当前版本工作区的 `tools/fm9g_grounding/cloud_env.sh`。初始化不创建或覆盖训练 head；在线推理继续使用 Git LFS 下载的部署头。
