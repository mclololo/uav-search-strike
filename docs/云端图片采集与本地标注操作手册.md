# 云端图片采集与本地标注操作手册

> 2026-10-08 新实例已恢复，当前 SSH 端口是 30624。当前数据盘、原图采集、人工标注及 FCOS 检测头训练请按 [新实例恢复与九格采集训练](新实例恢复与九格采集训练_20261008.md) 执行。下文保留旧实例的 YOLO 预标注操作记录，旧端口及阶段性状态不能直接当作当前配置。

原操作记录更新日期：2026-09-22

本手册用于在 GPUFree 云端仿真中保存前视相机原图和当前 YOLO 检测结果，再将整批数据下载到本地 Windows，通过浏览器标注工具直接导出自动标签或进行人工修正。

YOLO 在这条流程中只作为离线教师模型和预标注工具。正式启用九格模型执行比赛任务时，搜索、识别、打击、返航和异常恢复阶段都必须禁用 YOLO。

## 2. 每次开机先检查数据盘

进入云服务器桌面后打开终端，执行：

```bash
mountpoint /home/ubuntu/fm9g-data
df -h /home/ubuntu/fm9g-data
```

正常情况下第一条命令会显示：

```text
/home/ubuntu/fm9g-data is a mountpoint
```

如果显示 `is not a mountpoint`，不要在云端 `ubuntu` 终端运行 `sudo mount --bind`。当前容器不会给这个桌面会话实际的挂载权限，会报“只有 root 用户能使用 --bind 选项”。

在**本地 Windows PowerShell** 中使用 root SSH 恢复已经建立的数据盘绑定：

```powershell
ssh -p 30698 root@120.209.70.195 "mountpoint /home/ubuntu/fm9g-data >/dev/null || mount --bind /root/gpufree-data/fm9g4b_grounding /home/ubuntu/fm9g-data; mountpoint /home/ubuntu/fm9g-data; df -h /home/ubuntu/fm9g-data"
```

端口随实例变化时，把 `30698` 替换为 GPUFree 控制台给出的最新端口。然后回到云端桌面的 `ubuntu` 终端复查：

```bash
mountpoint /home/ubuntu/fm9g-data
df -h /home/ubuntu/fm9g-data
test -w /home/ubuntu/fm9g-data/data/images && echo "data directory is writable"
```

只有确认它是挂载点并显示 `data directory is writable` 后才能开始采集。不要在未挂载时创建图像目录，否则数据可能写入容量较小的系统盘。2026-09-22 已通过 root SSH 恢复当前实例的挂载，数据盘后端中的已有批次仍然存在。

## 3. 启动仿真环境

### 3.1 终端 A：启动 ROS 环境

```bash
cd /home/ubuntu/catkin_ws
./sim_env_start.sh
```

该脚本开头会清理旧 ROS 和 Python 进程，所以必须先运行它，再启动终端 B、C 和 D。不要在采集过程中重复运行该脚本。

等待它打开 `LLM Mission (mission_once)`、`YOLO Detection`、ArUco、EGO Planner 和任务节点等窗口。暂时不要在 LLM 窗口输入任务。

### 3.2 终端 B：启动 MAVROS

另开一个终端：

```bash
source /home/ubuntu/catkin_ws/devel/setup.bash
roslaunch mavros px4.launch fcu_url:=udp://:20101@
```

保持该终端运行，不要在其中继续输入其他命令。

### 3.3 终端 C：启动 RflySim/PX4

再开一个终端：

```bash
cd /home/ubuntu/PX4PSP
./SITLRun.sh
```

等待 RflySim3D、CopterSim、QGroundControl 和 PX4 启动。保持该终端运行。

### 3.4 检查图像和飞控连接

另开临时终端执行：

```bash
source /home/ubuntu/catkin_ws/devel/setup.bash
timeout 10 rostopic echo -n 1 /mavros/state
timeout 10 rostopic echo -n 1 /rflysim/sensor1/img_rgb/header
rostopic info /objects
```

应当能看到 MAVROS 状态、一条图像 header，并且 `/objects` 有发布节点。`/objects` 只有检测到目标时才可能产生消息，所以没有立即显示检测框不一定表示采集程序故障。

## 4. 开始采集

在输入大模型任务之前打开终端 D，执行：

```bash
source /home/ubuntu/catkin_ws/devel/setup.bash
cd /home/ubuntu/model/experiments/fm9g4b_grounding/scripts/yolo_auto_20260920
RUN_ID="flight_$(date +%Y%m%d_%H%M%S)"
echo "$RUN_ID"
/home/ubuntu/.conda/envs/fm9g-train/bin/python capture_pseudo.py --run "$RUN_ID" --scene-id "$RUN_ID" --interval 1 --seconds 600 --max-frames 600
```

最后一条采集命令应当整行粘贴并按一次回车。不要在反斜杠续行提示符 `>` 后输入空行；空行会提前结束命令，随后出现 `--run：未找到命令`。

记下 `echo` 输出的 `RUN_ID`，下载时必须使用同一个值。以上参数最多采集 10 分钟，每秒最多保存 1 张，共不超过 600 张。

采集器只订阅图像和检测结果，不发布飞行指令，也不会控制无人机。保存的是干净的前视相机原图，识别框存放在 JSONL 中；它不会保存带窗口边框、文字或检测框的屏幕截图。

看到类似下面的输出后，说明采集已经开始：

```text
SAVED 1: matched boxes=2
```

## 5. 执行一次任务

确认终端 D 已开始采集后，在 `LLM Mission (mission_once)` 窗口输入任务，例如：

```text
飞机起飞，然后穿过框，再去识别二维码，然后再穿回框，接着去打击红色气球，完成后就回到起点并降落
```

让任务完整执行。采集期间可以查看 `YOLO Detection` 窗口，但不要把该窗口截图作为训练图片。

任务结束后，只在终端 D 按 `Ctrl+C`。等待看到：

```text
CAPTURE_FINISHED images=... matched=... pending_review=... output=...
```

`reason=interrupted` 表示用 `Ctrl+C` 正常提前结束，并非采集失败。不要在 MAVROS、SITL、环境启动或 LLM 窗口中误按 `Ctrl+C`。

如果要重启仿真再飞一次，必须使用新的 `RUN_ID`。一次完整飞行即一个 `scene_id`；同一次飞行若分段采集，各段要保持同一个 `scene_id`，后续数据集不能把同一场景的相邻帧拆到训练集和验证集。

## 6. 检查云端采集结果

仍在终端 D 中执行：

```bash
echo "$RUN_ID"
ls -lh "/home/ubuntu/fm9g-data/data/images/$RUN_ID"
cat "/home/ubuntu/fm9g-data/data/images/$RUN_ID/capture-summary.json"
find "/home/ubuntu/fm9g-data/data/images/$RUN_ID" -maxdepth 1 -name 'frame_*.png' | wc -l
```

每个批次目录应包含：

```text
frame_000000.png
frame_000001.png
...
pseudo.jsonl
capture.json
capture-summary.json
```

`pseudo.jsonl` 中 `detection_status=matched` 表示找到了同一 ROS 时间戳和 frame_id 的检测结果；`detection_status=missing` 表示没有配对到检测消息。`missing` 是未知状态，不能直接当作“画面中没有目标”。

## 7. 下载整个批次到本地

在本地 Windows 打开 PowerShell。把 `$RunId` 改为终端 D 中实际记录的值：

把下面整行中的示例批次名替换为实际 `RUN_ID`，然后整行粘贴并按一次回车：

```powershell
$RunId = "flight_20260922_120000"; $LocalRoot = "C:\Users\ASUS\Desktop\uav-ss\原始图像"; New-Item -ItemType Directory -Path $LocalRoot -Force | Out-Null; scp -P 30698 -r "root@120.209.70.195:/home/ubuntu/fm9g-data/data/images/$RunId" "$LocalRoot"
```

分号用于分隔四条 PowerShell 语句。不能删掉 `$RunId` 与 `$LocalRoot` 之间的分号；否则两个赋值会连成一条无效语句，两个变量都不会生效。

`scp` 的端口参数是大写 `-P`。首次连接若提示主机指纹，应先与 GPUFree 控制台显示的实例信息核对。输入密码时终端不回显字符是正常现象；不要把密码写入脚本或手册。

下载后检查文件数：

```powershell
(Get-ChildItem -LiteralPath "$LocalRoot\$RunId" -Filter 'frame_*.png').Count
(Get-Content -LiteralPath "$LocalRoot\$RunId\pseudo.jsonl" -Encoding UTF8).Count
```

必须保留整个 `<RUN_ID>` 子目录及其原名称，不要把图片平铺到 `原始图像` 根目录，也不要只下载 PNG。标注工具需要同目录的 `pseudo.jsonl`，其中的图片路径和 `scene_id` 也依赖批次名。

## 8. 在本地打开自动标注

1. 用 Chrome 或 Edge 打开 `C:\Users\ASUS\Desktop\uav-ss\标注工具\annotate.html`。
2. 点击“选择采集目录”。
3. 选择 `C:\Users\ASUS\Desktop\uav-ss\原始图像\<RUN_ID>` 这个具体批次目录，并允许浏览器读取目录。
4. 页面会自动读取同目录的 `pseudo.jsonl`，显示 YOLO 的框、类别和置信度。

如果页面显示图片但目标框为 0，依次检查：

1. 选择的是具体 `<RUN_ID>` 目录，而不是上一级 `原始图像`。
2. 目录中存在 `pseudo.jsonl`。
3. 当前图片在 JSONL 中是 `matched`，而不是 `missing`。
4. 刷新页面后重新选择目录；必要时使用页面的导入标注功能选择 `pseudo.jsonl`。

## 9. 选择一种标注方式

### 9.1 直接使用 YOLO 结果

如果本批训练数据按当前计划直接使用 YOLO 预标注，点击“导出 YOLO 标注”。不需要逐张画框、选择类别或点击“确认并下一张”。

导出文件名为：

```text
<RUN_ID>_yolo_training.jsonl
```

该文件只包含配对成功且有有效检测框的图片，记录会标记为 `annotation_source=yolo_ros`、`review_status=auto_accepted`、`human_reviewed=false`。`missing`、空框和无效检测不会被当成负样本导出。

### 9.2 人工修正后导出

需要提高标签质量或制作验证、测试集时，逐张复核：

1. 用选择工具点击已有框，拖动框或角点修正位置。
2. 选中框后点击类别，可修正错误颜色或目标类型。
3. 对漏检目标切换到画框工具，选择类别后拖动绘制。
4. 删除明显误检框。
5. 确认无误后点击“确认并下一张”。
6. 只有确定画面中没有目标时才点击“确认无目标”。
7. 严重模糊、遮挡或无法判断时点击“跳过”，不要猜测。

气球框只覆盖可见气球主体，不包含小车、绳线，也不补画被遮挡的部分。方框目标始终采用一致的外边界定义。

完成后点击“导出已复核标注”，得到：

```text
<RUN_ID>.jsonl
```

只有已经确认的图片会进入该文件。浏览器本地进度不能替代导出文件，离开页面前必须实际执行导出。

浏览器通常把文件保存到 `下载` 目录。将最终使用的文件放到：


自动标签和人工复核标签不要同时作为同一张图片的两个训练版本。用于正式评估的验证集和测试集应来自独立飞行，并使用人工复核标签。


## 11. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 采集器提示数据目录不是挂载点 | 返回第 2 节恢复 bind mount，确认后使用新的 `RUN_ID` 重启采集 |
| 30 秒内没有第一张图 | 检查 RflySim、`sensor_pkg/main.py` 和 `/rflysim/sensor1/img_rgb` |
| 图片能保存但大部分是 `missing` | 检查 YOLO 窗口和 `/objects` 发布节点；这类图片保留供人工补标，不能当负样本 |
| 标注页面没有自动框 | 选择具体批次目录并确认同目录有 `pseudo.jsonl`，不要只选择 PNG |
| 二维码没有识别出来 | 与前视图片采集是两条链路；只要原图话题仍有数据，采集可以继续，另行排查 sensor2/ArUco |
| 任务重启后时间戳倒退，采集器停止 | 等仿真重新就绪后用新的 `RUN_ID` 开始新批次 |
| 本地目录已经有同名批次 | 不要覆盖；先核对来源，或重新采集时使用新的时间戳批次名 |
| 实例准备释放 | 数据盘不会随实例镜像保存；先把需要的全部批次和标签下载到本地 |
