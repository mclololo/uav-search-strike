# 九格训练结果和对照图下载到本地

更新日期：2026-09-23。

本文用于把训练结束后的权重、日志、数据划分、评测结果和对照图下载到 Windows。示例针对本次 `grounding-r16_20260923_111402`，每条命令均为完整单行，不使用续行反斜杠或反引号。

本次文件核对时，本地已存在两个 epoch 的权重、训练配置和 `balloon-comparison.png`。可直接补充尚未下载的评测结果、日志和数据划分；不用重复下载已经核对一致的文件。

## 1. 要保存哪些文件

以下云端相对路径均以 `/home/ubuntu/model/experiments/fm9g4b_grounding` 为起点。

| 内容 | 云端位置 | 用途 |
| --- | --- | --- |
| 两轮 LoRA 权重和配置 | `checkpoints/grounding-r16_20260923_111402/` | 包括 `epoch-01`、`epoch-02`、`best.json`、训练配置和提示词 |
| 训练日志 | `logs/grounding-r16_20260923_111402.log` | 查看训练过程、报错及完成标志 |
| 数据划分 | `data/dataset_20260923_111402/` | `train.jsonl`、`val.jsonl`、`test.jsonl` 和统计摘要 |
| 验证集评测 | `eval/grounding-r16_20260923_111402-val/` | 指标、逐图预测、评测配置 |
| 测试集评测 | `eval/grounding-r16_20260923_111402-test/` | 指标、逐图预测、评测配置及生成的对照图 |
| 对照图片 | `eval/grounding-r16_20260923_111402-test/balloon-comparison.png` | 左列人工标注、中列原始模型、右列本轮 LoRA |

注意区分：权重目录里的 `metrics.jsonl` 是训练 loss 记录；评测目录里的 `metrics.json` 才包含定位精度与推理耗时。只下载权重目录，无法完整分析识别效果和速度。

## 2. 云端确认文件可读取

在**云服务器桌面的 ubuntu 终端**执行：

```bash
cd /home/ubuntu/model/experiments/fm9g4b_grounding
mountpoint /home/ubuntu/fm9g-data
ls -lh checkpoints/grounding-r16_20260923_111402/epoch-02/adapter_model.safetensors
ls -lh data/dataset_20260923_111402/test.jsonl
ls -lh eval/grounding-r16_20260923_111402-val/metrics.json eval/grounding-r16_20260923_111402-test/metrics.json
ls -lh eval/grounding-r16_20260923_111402-test/balloon-comparison.png
```

训练和评测应已完成再下载。服务器保持开机，但下载无需运行仿真或加载模型。

若重启后不是挂载点，按现有人工 SSH 方式，在**本地 Windows PowerShell**执行：

```powershell
ssh -p 30698 root@120.209.70.195 "mountpoint -q /home/ubuntu/fm9g-data || mount --bind /root/gpufree-data/fm9g4b_grounding /home/ubuntu/fm9g-data"
```

然后回云端重新执行上面的检查。只有 PNG 缺失时，需要先生成对照图；不影响先下载其他已经存在的结果。

## 3. 本地建立保存目录

从这一节开始，除特别标明的云端命令，均在**本地 Windows PowerShell**执行。不要在云端终端粘贴 `C:\Users\...`。

```powershell
$ResultDir = 'C:\Users\ASUS\Desktop\uav-ss\训练结果\grounding-r16_20260923_111402'
New-Item -ItemType Directory -Force -Path $ResultDir | Out-Null
New-Item -ItemType Directory -Force -Path "$ResultDir\eval","$ResultDir\logs","$ResultDir\data","$ResultDir\scripts" | Out-Null
```

后续命令沿用这个 PowerShell 窗口。新开窗口后先重新执行本节，恢复 `$ResultDir`。云端的 `$RUN` 等变量不会自动传到本地。

本文 SSH 端口为 `30698`，如果控制台显示新端口，统一替换下面的端口。SSH 使用小写 `-p`，SCP 使用大写 `-P`。要求输入密码时输入当前实例密码，输入过程不回显。

## 8. 核对下载是否完整

每条 `scp` 结束后返回 PowerShell 提示符，再执行下一条。如果有错误信息，先解决该条传输问题。`scp` 不提供这里的断点续传功能，重新下载会重新传输并覆盖目标中的同名文件。

查看本地文件：

```powershell
Get-ChildItem -LiteralPath $ResultDir -Recurse -File | Select-Object FullName,Length
```

关键文件检查：

```powershell
Test-Path -LiteralPath "$ResultDir\epoch-02\adapter_model.safetensors"
Test-Path -LiteralPath "$ResultDir\epoch-02\adapter_config.json"
Test-Path -LiteralPath "$ResultDir\data\dataset_20260923_111402\test.jsonl"
Test-Path -LiteralPath "$ResultDir\eval\grounding-r16_20260923_111402-test\metrics.json"
Test-Path -LiteralPath "$ResultDir\eval\grounding-r16_20260923_111402-test\predictions.jsonl"
```

以上应分别返回 `True`。存在性检查不能证明文件完整，建议再校验最佳权重：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath "$ResultDir\epoch-02\adapter_model.safetensors"
```

本轮已完成评测记录中的最佳权重 SHA-256 是：

```text
d44a4064b4a884904af586f81a3f161b5e4c45173b6075ddde43bd8e60a204d6
```

哈希大小写不影响比较。本轮该文件大小应为 `84514056` 字节。换成其他训练轮次时，以该轮的权重和评测记录为准。

若要核对对照图，可在本地 PowerShell 分别计算云端和本地哈希，两者应一致：

```powershell
ssh -p 30698 root@120.209.70.195 "sha256sum /home/ubuntu/model/experiments/fm9g4b_grounding/eval/grounding-r16_20260923_111402-test/balloon-comparison.png"
Get-FileHash -Algorithm SHA256 -LiteralPath "$ResultDir\balloon-comparison.png"
```

最后一条针对第 6 节单独下载的图片；如果只下载整个测试目录，使用其 `eval` 子目录中的图片路径。

## 10. 常见问题

| 现象 | 处理 |
| --- | --- |
| 提示不认识 `C:\Users\...` 或 `New-Item` | 命令执行在云端了，换到本地 Windows PowerShell |
| `$ResultDir` 为空或目标路径报错 | 在同一个 PowerShell 窗口重新执行第 3 节 |
| `Connection refused` / 连接超时 | 确认实例开机，以及控制台最新 IP、SSH 端口 |
| 权重或原图 `No such file` | 检查数据盘挂载和具体路径；不要在未挂载目录重新创建假目录 |
| PNG `No such file` | 先确保绘图命令成功生成图片，下载操作不会自动绘图 |
| 下载后只有训练 loss，没有精度或耗时 | 还缺第 5 节的评测目录 |
| 本地多了一层同名训练目录 | 权重下载的目标应为父目录 `训练结果`，其他内容按各节指定目标保存 |

后续换训练轮次时，替换所有命令中的训练目录名、数据集目录名和对应飞行原图目录；数据集名以该轮 `train-config.json` 为准，不必与训练目录的时间戳相同。
